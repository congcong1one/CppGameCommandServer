# AI自治与代码所有权协议

核心原则：AI Coding 是需要主动训练的工程能力，但没有独立判断、测试预言和故障恢复能力，就没有资格扩大 Agent 权限。采用“首次认知形成与后续工程交付阶段性分开、整体路线持续融合”的方式。

## 四级自治

| 等级 | 人的责任 | Agent可做 | 禁止 |
|---|---|---|---|
| AI-0 闭卷形成 | 设计、首版、最小测试、解释 | 澄清约束、分级提示、官方资料、首版后的Review | 首版前给可复制完整实现 |
| AI-1 教练/Review | 主写关键路径；逐条决定建议 | 测试矩阵、反例、故障注入、Review、局部修复建议 | 自动接受整份Diff；把Agent解释当作用户掌握 |
| AI-2 受约束委派 | 先写任务简报；审完整Diff；硬验证 | 非核心样板、已理解领域、边界清晰的多文件实现 | 未定义测试预言就委派；跳过Diff Review |
| AI-3 Agent主导交付 | 需求拆解、关键约束、风险、发布/回滚、最终批准 | 主导有边界的端到端实现和验证 | 在用户不能独立判断的领域主导；无硬证据宣称完成 |

等级按任务或模块记录，不是用户的永久级别。Gate映射：Gate A核心任务限AI-0/1；Gate B关键风险路径仍先由用户设计和主写，非核心交付可进入AI-2；Gate C才验证AI-3。

## 升级与回退

- AI-0 → AI-1：用户先完成可构建第一版，能解释关键路径和一个失败路径。
- AI-1 → AI-2：24—72小时后能在陌生变体/缺陷Diff中复调核心模型；能用测试/调试工具定位问题；至少独立识别并处理一个真实或注入缺陷。
- AI-2 → AI-3：至少两次受约束委派通过硬验证；完整审过Diff；至少一次拒绝/修正Agent建议；有运行、停止、故障处理和回滚说明。
- 无法解释关键路径、无法发现高风险改动或无法无Agent写简化版时，该模块回退一级并做最小闭卷复现；不连带推翻其他模块证据。

## AI-0/1核心模块首次实现规则

1. 从真实场景开始，用户先写一个与当前任务匹配、可被实验推翻的最小认知产物：一句预测、行为图、所有权/线程草图、实验记录或精简设计卡均可；只填写适用项，不完成形式化问卷。
2. Agent提供当前实验的最小理论包、接口约束、关键API文档或编译命令，但不首次直接输出完整核心文件，也不提前泄露实验结论。
3. 用户增量写出第一版并观察硬证据后，先解释预测与结果的偏差；Agent再进行完整Review、反例设计和修复建议。
4. 不引入用户未主动选择、无法解释的抽象、模板技巧、协程或框架。
5. 用户逐条决定接受、拒绝或改写建议，并能解释理由。

## AI-2/3任务简报

委派前由用户写清：

- 目标与非目标。
- 相关模块、调用链和必要上下文。
- 必须保持的接口/行为与禁止改动。
- 正常、边界、失败路径的测试预言。
- 风险、失败处理、发布/回滚方式。
- 完成标准和允许Agent自主决定的范围。

委派后必须审完整Diff，而不只看Agent摘要；运行构建、自动测试、Sanitizer、故障注入或运行日志中的相关硬验证；关键判断记录为接受、拒绝或改写。

## 所有权验收

- ☐ 用户能画出模块所有权和线程图。
- ☐ 用户能在24—72小时后处理一个陌生变体、缺陷Diff或简化重建，而不是只复述原答案。
- ☐ 用户能解释一个失败路径和一个主动制造的Bug。
- ☐ Git提交体现渐进实现，而不是一次性生成。
- ☐ 用户能回答为什么选择当前方案，而不是只说“AI建议”。
- ☐ AI-2/3任务有任务简报、完整Diff Review和硬验证记录。
- ☐ 贡献边界诚实标注为用户主写、Agent生成、用户改写/验证。

## 模块完成定义（DoD）

- ☐ 相关代码能够构建，自动测试通过。
- ☐ 至少有正常、边界、失败三类路径中的代表性测试。
- ☐ 与任务匹配的记录明确场景、预测，以及适用的所有权、线程、关闭/停止、错误路径、AI等级和委派边界。
- ☐ 至少有一个可复现Bug或排障记录，完成修复与回归。
- ☐ 用户能在24—72小时后完成一次陌生变体/缺陷诊断/简化重建；提交历史体现渐进实现。
- ☐ Agent参与部分经过用户Review和硬验证；不能解释的生成代码不得进入能力证据。
- ☐ 适用时有一条AI判断校准：委派前收益/风险/证据预测，与验证后的实际偏差。

## Agent可以直接做的工作

- 解释文档、API、编译错误和运行错误。
- 审查生命周期、边界、并发、异常和停止流程。
- 生成测试矩阵、故障注入方法和面试追问。
- 协助建立最小复现和排查假设。
- 整理学习日志、架构说明和阶段验收。
- 按当前自治等级完成非核心样板、测试夹具、脚本和文档。

## 证据与指标

只保存能够复核的最小证据，不保存冗长Prompt或聊天转录。建议记录：任务耗时、Agent迭代次数、首轮验证结果、Review发现、回归次数、无Agent复现结果，以及一次被拒绝/修正的建议。

代码行数、工具使用时长、主观“10x”和“AI几乎没Bug”不是能力证据。对外陈述必须区分用户决策/主写、Agent生成、用户Review/改写和自动验证。

## 用户要求直接完成大量代码时的处理

- 先确认工作模式与当前自治等级。
- 学习模式AI-0/1核心模块，要求用户先写最小预测/设计产物并增量完成第一版。
- AI-2/3可以直接委派，但必须先有任务简报和测试预言。
- 调试模式可给完整补丁，但必须解释证据、根因和回归测试；补丁是否计入学习证据仍按所有权验收。
- 工作交付/救火模式可更直接生成代码；生成结果在用户Review和复现前，不计入学习证据。
