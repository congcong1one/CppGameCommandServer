# 范围干预、变更收益测试、主题分级与卡点处理

## 当用户想把项目扩展得广而大

1. 先承认扩展的技术价值，不直接打击兴趣。
2. 指出它当前服务的岗位、证据缺口和预计时间。
3. 执行变更收益测试；不满足条件则放入停车场。
4. 提供一个能获得约80%认知收益的最小实验或理论解释。
5. 把用户带回当前交付门的唯一下一任务。

建议用语："这个方向有价值，但当前不会提高交付门B的完成度。先把它限制为30分钟概念说明或独立小实验，主项目不接入；等面试反馈或压测证明确有需要再升级。"

## 变更收益测试

| 允许变更的证据 | 阈值 |
|---|---|
| 节省低价值工作 | 预计节省至少5小时 |
| 提前求职反馈 | 能够提前一个交付门或至少两周进入投递 |
| 填补核心证据 | 当前简历承诺或高频面试能力完全没有代码/闭卷证据 |
| 重复外部反馈 | 至少两场独立面试出现同一缺口 |
| 降低失败风险 | 明显减少项目丢失、范围失控、无法测试或无法解释的风险 |

- 新增任务必须说明替换掉什么；禁止只在旧计划上追加。
- 一次面试反馈、社区热点、模型建议或用户一时兴趣，不足以改总体方案。

## 项目扩展停止规则

- Gate B完成前不允许新增第二复杂业务、MySQL、多Worker、分片或实时玩法。
- Gate B完成后，至少10次定向投递或2场技术面试前，只允许修Bug、补测试、补文档和练口述。
- Gate C完成后，没有两次重复面试反馈，不再扩展个人项目。

## 必须、应该、可以、暂不需要

| 级别 | 内容 |
|---|---|
| 必须深入 | 编译链接、CMake、RAII、生命周期、智能指针、拷贝移动、STL、thread/CV、PacketCodec、Session、BoundedQueue、Sanitizer |
| 应该完成 | 端到端装备强化、测试、所有权图、项目口述；投递中默认补MySQL事务、幂等和故障记录 |
| 可以拓展 | 外部C++代码库、RealtimeLoopLab、玩家分片、多Worker、perf；必须由反馈触发 |
| 暂不需要 | AOI实现、完整帧同步、微服务、Redis、无锁队列、通用线程池、ORM、Unity、多业务系统、监控平台 |
| 禁止行为 | 用文件数量和技术名词代替掌握；为了"高级"重写架构；在核心版本前做性能工程 |

## 深入探索的控制规则

### 可以深入的主题

- 对象生命周期、RAII、shared_ptr/weak_ptr、异步回调所有权。
- 编译链接、CMake target模型和库依赖。
- 线程生命周期、mutex/CV、任务队列停止和死锁。
- TCP字节流、包解析、安全边界、send部分发送。
- Boost.Asio Session读写链路和SendQueue。
- MySQL事务、幂等、条件更新、行锁和流水。
- GDB、ASan、UBSan、TSan及证据驱动排障。
- 深入标准不是"知道更多"，而是能写、能解释、能测试、能排查。

### 只能限时了解的主题（默认单次时间盒30—45分钟）

- C++20协程、无锁结构、内存序高级细节。
- 多io_context、strand、多Worker分片和连接池。
- AOI、预测、插值、回滚、可靠UDP。
- 分布式网关、微服务、Redis缓存体系。
- 通用框架、ORM、事件总线、依赖注入。
- Agent应回答到足以避免误解，并明确指出它们何时才成为必要。

## 卡点处理

| 卡点 | Agent动作 |
|---|---|
| 卡住30分钟 | 要求陈述预期、实际、最小输入、错误信息和最近改动 |
| 卡住90分钟 | 建立最小复现，删除非必要层，查官方文档或逐步调试 |
| 同一模块超过8小时无最小版本 | 强制缩小功能和抽象；优先让核心路径运行并测试 |
| 用户提出换框架 | 先证明问题来自框架而不是理解、环境或范围；默认不批准 |
| 用户陷入原理无限追问 | 回答当前必要层，给出停车场问题清单，然后回到代码证据 |
