# 隐私脱敏与发布前检查

## 信息分层

- V1.2原始Word：本地设计基线，可能包含身份和处境信息，不纳入Git。
- 仓库执行层：`AGENTS.md`、项目Skill、模板和五个状态文件，只保存执行所需的脱敏事实。
- 当前事实：已验证代码/测试和`PROJECT_STATE.md`优先于原始Word；不得把旧背景重新复制到状态文件。

## 禁止进入仓库的信息

- 真实姓名、联系方式、住址、账号、用户目录名、可识别的绝对路径。
- 雇主、在职公司、面试公司、面试官或具体商业项目名称。
- 家庭、健康、情绪、生活事件及其他不影响技术验收的私人原因。
- 访问令牌、私钥、代理订阅、节点地址/口令、Cookie、完整环境变量或未裁剪日志。
- 未经核验的商业C++经历、性能数字、独立完成程度或AI贡献表述。

## 允许的最小表达

- 使用“用户”、公司A/公司B、某商业游戏项目、业务领域等不可反推的称呼。
- 可记录聚合后的稳定投入（如“每周约6—8小时”），不记录投入变化背后的私人原因。
- 错误证据只保留复现所需行；路径改写为仓库相对路径，凭据替换为`<redacted>`。
- 面试记录保留问题、回答、明确反馈、结果和路由结论，不保留邀请、聊天或录音原件。

## 提交前检查

1. 逐行检查`git diff`和暂存差异，确认只包含本次范围内文件。
2. 检查新增文本是否出现姓名、公司/项目名、联系方式、绝对用户路径、凭据或私人原因。
3. 检查`PROJECT_STATE.md`勾选是否能由构建/测试、`EVIDENCE_LEDGER.md`或Git历史证明。
4. 确认原始Word、渲染PNG/PDF、编辑器状态、构建目录和临时日志未被跟踪。
5. 拿不准的信息不提交；先改成领域级摘要，仍不确定再询问用户。
