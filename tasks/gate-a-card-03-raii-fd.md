## 本卡要证明什么

- 用户能用对象生命周期管理一个Linux文件描述符，而不是依赖调用方记住每条`close`路径。
- 用户能区分资源值、资源所有权和对象移动，避免泄漏与重复关闭。
- 用户能用真实文件描述符证明析构与移动行为，而不只观察打印日志。

## 固定场景

实现一个C++17最小类型，它唯一拥有一个Linux文件描述符，资源值用`int`保存。类型接管调用方已经获得的fd，不调用`dup`，不讨论内存、Session、线程、智能指针或通用句柄框架。目标是让提前返回、作用域退出和对象移动都不会泄漏或重复关闭fd。

### 实验A前必读（约8分钟）

**文件描述符是什么**

- 在当前Linux进程里，文件描述符是一个非负整数句柄，用来引用内核维护的已打开I/O资源；文件、管道和socket都可以通过fd操作。
- fd数字不是资源本体，也不是所有权。谁负责最终调用`close(fd)`，谁才是本卡讨论的所有者。
- 本卡的包装类型用`-1`表示“不拥有fd”。这是类内部约定；有效Linux fd为非负数。

**RAII解决什么问题**

- RAII把“资源有效期”绑定到C++对象生命周期。对象成功接管fd后，析构负责释放；正常离开作用域、提前`return`或异常展开时，都由同一个析构路径收尾。
- 当前实验只需要建立“接管一个fd → 离开作用域 → 有效fd被关闭”的闭环，不需要先掌握完整智能指针体系。

**本实验使用的系统调用**

- `pipe(int pipefd[2])`成功返回`0`，并写入两个fd：`pipefd[0]`是读端，`pipefd[1]`是写端；失败返回`-1`。
- `close(fd)`成功返回`0`；失败返回`-1`并设置`errno`。成功关闭后，该fd数字可以被系统重新使用。
- `fcntl(fd, F_GETFD)`可用于观察fd是否仍有效：有效时返回描述符标志；无效fd返回`-1`并令`errno == EBADF`。

**实验A关键易错点**

- `pipe()`产生两个fd。若包装器只接管其中一个，另一个仍由测试代码负责关闭；否则测试自身会制造与RAII类型无关的泄漏。
- 只打印“析构被调用”不能证明fd真的关闭，必须观察系统调用结果。

### 实验B/C前再读（约8分钟）

- 对`int`而言，默认移动与复制效果相同：都只是复制数字，不会自动转移内核资源所有权。
- 唯一所有权类型必须禁止拷贝；移动构造需要让目标接管fd，并把源对象改为无效状态。
- 移动赋值还要先处理目标原来拥有的fd，否则旧资源会泄漏；完成后仍只能有一个有效所有者。

### 实验D前再读（约5分钟）

- 关闭后的fd数字可能很快被系统分配给另一个资源。保存着旧数字的“伪所有者”若再次`close`，可能关闭一个完全不同的新资源，这比单纯收到`EBADF`更危险。
- Linux上的`close()`失败主要用于诊断；不能不加判断地重试，因为fd可能已经释放并复用。析构函数也不应把关闭失败作为普通异常抛出。

### 本卡明确不展开

- `dup/dup2`共享底层open file description、跨线程关闭竞态、`fsync`持久化、不同Unix对`close(EINTR)`的可移植差异。这些有价值，但不影响当前唯一所有权实验，后续由真实问题触发。

## 学习循环

本卡不做连续理论问答，按四个小实验逐步形成实现。运行前先形成一个可证伪预期，运行后保存实际结果；用户的自发表达、连续Diff和验证决策已能显示“原模型 / 实际证据 / 模型改变”时，由Agent据实汇总，不要求用户再按固定三行模板回复。预测错误不是失败，能够根据证据解释和修正才是训练目标。

### 实验A：作用域退出

- 使用`pipe()`获得真实fd，把其中一个fd交给你的最小所有权类型。
- 让对象离开局部作用域，再用`fcntl(fd, F_GETFD)`观察该fd是否仍有效。
- 先只实现足以让实验A成立的构造、无效状态和析构，不提前写完所有接口。

### 实验B：移动构造

- 把所有者移动到一个新对象，观察源对象和目标对象状态。
- 让两个对象依次析构，用系统调用结果确认资源只关闭一次。

### 实验C：移动赋值

- 目标和源最初各自拥有一个不同fd，再执行移动赋值。
- 观察目标旧fd、新fd和源对象在赋值前后的状态，检查是否泄漏或重复关闭。

### 实验D：诊断Agent注入的陌生错误

- Agent在已通过实验A—C的实现中只注入一个未公开的所有权错误；改动必须可恢复、保持工程可构建，并且当前主程序和Sanitizer表面正常，不同时破坏多个不变量。
- 用户先Review代码并提出一个所有权不变量假设；Agent在用户提交诊断前不运行或透露会直接暴露注入点的探针。
- 诊断后用仓库外临时探针验证源对象状态和重复关闭，再恢复正确实现并回归实验A—C。只有在因果链仍不清楚时，才追加强制fd数字复用实验；不为展示风险而扩张主程序结构。

完成实验后，再用一小段话解释：为什么复制一个`int fd`不等于获得独立所有权，以及析构中的`close()`失败为什么不能简单按普通业务异常处理。

## 首版实现约束

- 实现一个只拥有单个`int`文件描述符的最小类型，名称和文件布局由用户决定。
- 无效状态统一使用一个明确值。
- 有效资源在对象析构时关闭一次；无效资源不关闭。
- 禁止拷贝构造和拷贝赋值。
- 支持移动构造和移动赋值；移动后源对象不再拥有资源。
- 提供观察当前描述符和有效状态所需的最小接口；暂不增加共享所有权、模板、继承或通用句柄框架。
- 使用C++17和Linux系统调用，不引入第三方库。

## 验收

- 从仓库根目录配置、构建并运行成功。
- 真实文件描述符离开作用域后已关闭。
- 移动后源对象无效，目标对象成为唯一所有者。
- 移动赋值时目标原有资源没有泄漏。
