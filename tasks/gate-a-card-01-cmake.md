# Gate A / 卡1：15分钟多文件CMake工程

> 当前自治等级：**AI-0（闭卷形成）**。本卡只给任务约束和验收，不给实现答案。计时结束后才进入AI-1 Review。

## 本卡要证明什么

- 用户能从空仓库建立最小CMake target，而不是只会修改现成工程。
- 用户知道声明、实现、编译单元和链接目标分别在哪里。
- 用户能保留原始错误，让后续Review基于证据而不是重新生成一套工程。

## 开始前（不计入15分钟）

1. 在仓库根目录确认`git status --short --branch`无意外改动。
2. 打开终端，准备15分钟计时器。
3. 关闭Agent自动改文件能力；可以看本卡、CMake官方命令文档和本机`cmake --help-*`，不能让Agent生成文件、代码或完整答案。

## 任务

建立一个最小工程，满足：

- 一个可执行入口。
- 一个独立头文件，声明入口会调用的函数。
- 一个独立实现文件，实现该函数。
- 根目录一个`CMakeLists.txt`，把所需编译单元组成一个可执行target。
- 程序运行时输出一行可观察结果，且该结果来自独立实现文件中的函数。

名称和目录布局由用户决定；不要在本卡之外增加库、测试框架、安装规则或大型目录设计。

## 15分钟停止规则

- 计时结束立即停止新增功能，不因“只差一点”延长。
- 成功：保存文件和实际命令输出。
- 未成功：保留当前文件，记录最后一条命令、最小错误片段和自己的一个根因假设；不要删除现场后让Agent重做。

## 验证

依次验证：

```text
cmake -S . -B build
cmake --build build
运行 build 目录中生成的可执行文件
```

通过标准：配置、构建、运行均成功；输出符合预期。

## 提交给Agent Review的材料

- 实际耗时。
- `git status --short`；保留工作树中的`CMakeLists.txt`和新增源文件供Agent直接读取，不要为了“看起来干净”重写现场。
- 三条验证命令及最小结果；失败时给最后一条命令和最小错误片段。
- 先自行回答：
  1. 哪些文件是编译单元？
  2. 头文件为什么通常不单独编译？
  3. 哪一行定义了链接目标，哪些源文件进入该目标？
  4. 如果实现文件没有加入target，预期在哪个阶段失败，为什么？

Agent收到材料后切换到AI-1：先Review现有Diff和证据，再给最小修正或反例；不另起炉灶代写一套答案。
