第一课：从监听到收包

本课的唯一胜利条件：看到一段异步TCP代码时，能说清每一步何时完成、结果出现在哪里，以及谁必须继续存活。

先建立一张运行图

io_context→acceptor→async_accept→Session(socket)→async_read→PacketCodec→SendQueue / async_write

io_context是handler的执行场；acceptor只负责监听和产生已连接socket；每个Session拥有一个socket、读buffer、解析状态与发送队列。

异步API的共同语法：调用函数只登记操作并立即返回；完成结果不从调用点return，而是稍后以error_code和结果参数进入handler。官方文档把返回类型写成DEDUCED，因为它由completion token决定；当前普通lambda用法可理解为返回void。

监听连接：4个对象/API

using tcp = boost::asio::ip::tcp;

boost::asio::io_context io;
tcp::endpoint endpoint(tcp::v4(), 7000);
tcp::acceptor acceptor(io, endpoint);

acceptor.async_accept(
    [](boost::system::error_code ec, tcp::socket socket) {
        // ec == 0: socket是一条新连接
    });

std::size_t handlers = io.run();
  • tcp::v4()选择IPv4；7000是主机字节序端口。
  • tcp::acceptor(io, endpoint)的便捷构造会open、bind并listen；构造函数没有返回值，失败默认抛异常。
  • async_accept(handler)立即返回。handler参数ec说明成败，socket是成功连接。
  • io.run()阻塞执行handler，返回本次执行的handler数量；没有工作或被stop后结束。

读取游戏包：不要把TCP当消息队列

TCP只提供有序字节流。一次客户端发送可能被服务端分成多次读取；多次发送也可能合并在一次读取里。第一版协议可使用“固定4字节长度头 + 包体”。

// 先精确读满固定包头
boost::asio::async_read(
    socket,
    boost::asio::buffer(header),
    [self](boost::system::error_code ec, std::size_t bytes) {
        // 校验header中的body_length，再发起下一次async_read读取包体
    });

async_read参数依次是流、可写buffer、完成handler。它通过若干次底层async_read_some填满buffer或遇错。handler中的bytes是实际写入buffer的字节数。

生命周期红线：boost::asio::buffer(header)只是“地址+长度”视图，不拥有header。异步操作完成前，Session、socket、header和捕获它们的handler都必须有效。

发送响应：为什么需要SendQueue

boost::asio::async_write(
    socket,
    boost::asio::buffer(outbound_message),
    [self](boost::system::error_code ec, std::size_t bytes) {
        // 完成后才能弹出当前消息并启动下一次写
    });

async_write会通过若干次部分发送，直到全部buffer写完或发生错误。它不允许你在前一次组合写完成前对同一socket再启动另一次写；SendQueue的职责是保持消息内存有效、串行化写操作并限制积压。

关闭链路

boost::system::error_code ignored;
socket.cancel(ignored);
socket.shutdown(tcp::socket::shutdown_both, ignored);
socket.close(ignored);

cancel让未完成异步操作进入完成回调，常见结果是operation_aborted；shutdown改变TCP收发方向；close释放本地socket。真正的Session还要让重复关闭、读错、写错和主动停止汇合到同一个幂等关闭状态。

三次检索练习

1. async_read调用返回时，header一定已经填满了吗？

不一定。调用只登记异步操作并立即返回；填满或出错时才调用handler。

2. 把局部std::string传给async_write后立即离开作用域安全吗？

不安全。buffer不拥有字符串内存，字符串必须持续有效到写handler执行。

3. 两次async_write可以同时操作同一个socket吗？

当前设计不可以。用SendQueue保证任一时刻只有一个组合写操作。

下一次实践的停止线

只做到：监听一个端口，接受连接，按“4字节长度头 + 包体”回显一条消息，并证明半包场景可工作。暂不加入协程、strand、多线程和通用框架。

完整参数与返回值见Boost.Asio TCP API速查。首要原始资料是Boost.Asio 1.83官方教程。任何一步不清楚，都可以继续问Agent并要求映射到当前Session对象和生命周期。
